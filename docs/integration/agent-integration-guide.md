# Agent Integration Guide

This guide shows how an agent should consume OpenTool Mesh without hard-coding a tool endpoint.

## Required Agent Flow

An agent should follow this order:

1. Decide the required capability.
2. Discover candidate tools by capability.
3. Resolve the selected tool identity through ENS.
4. Load the manifest from 0G Storage.
5. Verify manifest hash, owner, schema, and SDK compatibility.
6. Invoke the tool through AXL.
7. Store request, response, output, report, and trace artifacts in 0G.
8. Surface the trace/report in the dashboard or in the agent's own UI.

The reference capability is:

```text
solidity-static-analysis
```

## SDK Setup

Create a provider-backed client:

```ts
import {
  createOpenToolMeshClient,
  createProviderClientDeps,
  createProviderConfigFromEnv
} from "@opentoolmesh/sdk";

const config = createProviderConfigFromEnv(process.env, process.cwd());
const client = createOpenToolMeshClient(createProviderClientDeps(config));
```

For local development, leave `OTM_PROVIDER_PROFILE` unset or set it to `local`. For real provider acceptance, set `OTM_PROVIDER_PROFILE=provider-testnet` and configure ENS, 0G, and AXL values in `.env.provider`.

## Discover, Resolve, Verify

```ts
const capability = "solidity-static-analysis";
const candidates = await client.discoverTools({ capability, limit: 1 });
const selected = candidates[0];

if (!selected) {
  throw new Error(`No tool found for ${capability}`);
}

const identity = await client.resolveIdentity({ ensName: selected.ensName });
const manifest = await client.loadManifest({ manifestUri: identity.latestManifestUri });
const verification = await client.verifyManifest({
  identity,
  manifest,
  sdkVersion: "0.1.0"
});

if (!verification.ok) {
  throw new Error(`Manifest rejected: ${verification.errors.join(", ")}`);
}
```

Do not skip verification. This is where the agent proves the manifest hash matches ENS, the owner matches identity resolution, the schema is compatible, and the SDK version is accepted.

## Invoke Through AXL

```ts
const traceId = crypto.randomUUID();
const response = await client.invokeTool({
  capability,
  tool: identity,
  manifest,
  agentId: "my-agent",
  input: {
    source: soliditySource
  },
  traceId
});
```

The SDK validates input against `manifest.mcp.inputSchema`, sends the request through `manifest.invocation.axlPeerId` and `manifest.invocation.axlMethod`, then validates successful output against `manifest.mcp.outputSchema`.

## Persist Provenance

At minimum, persist:

- invocation request artifact
- invocation response artifact
- tool output artifact
- final report artifact
- execution trace

The trace should include:

- agent id
- requested capability
- tool identity
- manifest URI and hash
- input hash
- output hash
- invocation status
- artifact/report references
- 0G trace URI returned by `recordTrace`

The repository's provider smoke implementation is the concrete reference:

```text
scripts/provider-live-smoke.ts
```

## Rejection Behavior

If `verifyManifest()` returns `ok=false`, the agent must not invoke the tool. It should record or return a rejected status with the verification errors. The CLI command path demonstrates this behavior in:

```text
packages/cli/src/commands/call.ts
```

## Demo Command

For a full provider-backed agent run:

```sh
corepack pnpm provider:smoke -- --full
```

Then start the dashboard:

```sh
corepack pnpm dashboard:dev
```

The dashboard reads the latest successful trace mirror and displays the real 0G manifest, artifact, report, and trace URIs generated by the provider smoke run.
